# kanata の設定ファイル（.kbd）の手引き

この文書は、kanata 単体で使う（常駐サービスを使わず、生成済みの設定ファイルを kanata に読ませる）場合の、kanata の起動の方法と、設定ファイル（`.kbd`）の構成・編集・再生成の方法を説明する。常駐サービスは、編集した `.kbd` を使用しない（常駐サービスの設定は[設定リファレンス](settings.md)）。設定ファイルの仕組みは[kanata の設定ファイルの設計](kanata-kbd-design.md)にある。

---

## 1. kanata 単体で使う方法

kanata 単体で使う場合は、kanata 設定生成器（`nicola-kbdgen`）が配列定義から生成した設定ファイル（`kbd/` に生成済み）を、kanata に読み込ませる。設定ファイルは、配列プロファイル（一通りの配列と、その親指キー・NICOLA 切替キー・判定・送出の定義）と環境固有設定（[§2.1](#21-環境固有設定user-customkbd)）からなり、編集（[§2](#2-設定ファイルの編集)）か再生成（[§3](#3-設定ファイルの再生成)）で変更する。

```mermaid
flowchart LR
  SRC["配列定義 <br> 配列差分ファイル"] --> GEN["kanata 設定生成器 <br> （再生成。§3）"]
  GEN --> KBD["設定ファイル（§1.2） <br> 配列プロファイル・環境固有設定"]
  EDIT["編集（§2）"] --> KBD
  KBD --> KAN["kanata <br> （起動と停止。§1.3）"]
```

### 1.1 前提条件

- `kbd/` の生成済みの設定ファイルを使用するので、Rust は不要である（再生成する場合だけ必要。[§3](#3-設定ファイルの再生成)）。
- Linux では、権限の設定（[導入と利用 §2.1](usage.md#21-権限の設定)）が必要である。kanata は、[kanata のリリース](https://github.com/jtroo/kanata/releases)の v1.13.0-prerelease-1 以降を使用する（キーボードの再接続の修正〔[上流の #2129](https://github.com/jtroo/kanata/pull/2129)〕を含むバージョン。kanata-nicola での動作は **未確認**）。このバージョンにも残る再接続の不具合は[設計書 §10.4](design.md#104-キーボードの取得と再接続の制約linux)にある。
- NICOLA の ON/OFF は NICOLA 切替キーの方式（NICOLA 切替キーで、IME と一緒に切り替える。[導入と利用 §3.1](usage.md#31-nicola-入力の-onoff)）だけで、IME 同期は使用できない。

Windows で試用する場合は[Windows での利用](windows.md)を参照する。

### 1.2 生成済みの設定ファイル

`kbd/` には、次の生成済みの設定ファイルがある。

| ファイル | 種別 | 内容 |
|---|---|---|
| `kbd/nicola.kbd` | 配列プロファイル | NICOLA J型の標準配列、親指先行方式、ローマ字、半角/全角で切り替え |
| `kbd/nicola-lag-tolerant.kbd` | 配列プロファイル | 標準配列に、配列差分ファイル `practical` と `lag-tolerant` を重ねた配列（[配列差分ファイル §3](layout-overlays.md#3-同梱の配列差分ファイル)）。ほかは `kbd/nicola.kbd` と同じ |
| `kbd/user-custom.kbd` | 環境固有設定（[§2.1](#21-環境固有設定user-customkbd)） | 対象にするキーボード、Ctrl として扱うキー等。どちらの配列プロファイルも、同じディレクトリにあるこのファイルを `include` で読み込む（kanata をどのディレクトリで起動しても同じ） |

### 1.3 kanata の起動と停止

kanata を起動するときは、配列プロファイルを指定する。

```sh
kanata -c kbd/nicola.kbd
```

コピーして編集した設定ファイル（[§2](#2-設定ファイルの編集)）を使用するときは、そのファイルを指定する（例: `kanata -c ~/.config/kanata-nicola/kbd/nicola.kbd`）。kanata は設定ファイルを起動のときに読み込むので、編集した内容は、kanata を起動し直すと反映される。

停止するときは、kanata を実行している端末で Ctrl+C を入力する。

キーが意図しない動作をして Ctrl+C を入力できないときは、**左Ctrl+Space+Esc**（kanata の標準の操作）で非常停止する。

## 2. 設定ファイルの編集

変更する対象と方法は、次のとおり。

| 変更の対象 | 方法 |
|---|---|
| 対象にするキーボード、Ctrl として扱うキー、キーの再割り当て | 環境固有設定を編集する（[§2.1](#21-環境固有設定user-customkbd)） |
| 配列の一部の文字の割り当て | 配列プロファイルを編集する（[§2.2](#22-文字の割り当ての変更)） |
| 配列（配列差分ファイル）、親指キー、NICOLA 切替キー | 再生成する（[§3](#3-設定ファイルの再生成)） |

編集するときは、次の点に注意する。

- `kbd/` のファイルを、リポジトリの外（例: `~/.config/kanata-nicola/kbd/`）にコピーしてから編集する。リポジトリの中のファイルを編集すると、更新の取得（`git pull`）で同じファイルが変更されたときに衝突する。
- UTF-8 で保存する。ほかの文字コード（Shift_JIS 等）では、kanata が読み込めない。
- 取得した更新で `kbd/` の配列プロファイルが変更されたときは、改めてコピーして、編集していた箇所を同じように編集する。環境固有設定は別のファイルなので、そのまま使用できる。
- 編集した後は、設定ファイルの記述に誤りが無いかを検査し（[§2.4](#24-編集した設定ファイルの検査)）、kanata を起動し直す（[§1.3](#13-kanata-の起動と停止)）。記述は kanata の構文（kanata の[設定ガイド](https://github.com/jtroo/kanata/blob/main/docs/config.adoc)）に従う。

### 2.1 環境固有設定（user-custom.kbd）

環境固有設定は、利用環境に固有の設定（対象にするキーボード、Ctrl として扱うキー等）を記述するファイルである。項目は次のとおり。

| 項目 | 内容 | 記述方法 |
|---|---|---|
| `process-unmapped-keys yes` | `defsrc` に無いキー（Enter・BackSpace 等）も kanata で処理する | **変更しない**（`no` にすると、これらのキーが文字の送出より先に出力されることがある） |
| `log-layer-changes no` | レイヤの切り替えをログに出力しない。kanata は既定では出力し、親指キーを押すたびにレイヤの定義全体を出力する | 切り替えを確認する場合は `yes` にするか、kanata を `--log-layer-changes` 付きで起動する |
| `linux-dev-names-include` | 対象にするキーボードの名前（調べ方は[設定リファレンス §3.1](settings.md#31-設定値の調べ方)）。指定しない場合は、すべてのキーボードが対象になる | `defcfg` に `linux-dev-names-include ("名前1" "名前2")` を追加する |
| `linux-dev-names-exclude` | 除外するキーボードの名前 | `defcfg` に `linux-dev-names-exclude ("名前1" "名前2")` を追加する |
| `keys-as-ctrl` | 左右の Ctrl に加えて、Ctrl として扱うキー。デスクトップのキー配列の設定（xkb）で Ctrl に変更したキー（CapsLock 等）を指定する。指定しない場合は、NICOLA が ON の間、そのキーとの組み合わせがショートカットとして機能しない | CapsLock の場合は `(or (input real caps))`。指定しない場合は `(or)`。指定できるのは、配列プロファイルの `defsrc` にある修飾キーと `caps` である。ほかのキーは、配列プロファイルの `defsrc` にも追加する必要があるので、`--key-as-ctrl` を指定して再生成する（[§3](#3-設定ファイルの再生成)） |
| `defoverrides` 等（任意） | キーの再割り当て等の、追加する kanata の定義（例と注意点は[設定リファレンス §3.2](settings.md#32-追加の-kanata-の設定ファイル)） | このファイルに追加する |

### 2.2 文字の割り当ての変更

配列の一部の文字の割り当て（あるキーの単独面の文字等）は、配列プロファイルを編集して変更できる。再生成しないので、Rust は不要である。

変更する文字が多い場合や、常駐サービスでも同じ配列を使用する場合は、配列差分ファイルを作成して再生成する（[配列差分ファイル](layout-overlays.md)、[§3](#3-設定ファイルの再生成)）。

配列プロファイルでは、文字キーの面（単独面と、左・右の親指の面）ごとに、レイヤを 1 つ定義している。面の文字は、レイヤのキーの定義（`キー 動作` の組）と、文字の定義に、次の形で記述している。

| 記述する所 | 形 |
|---|---|
| レイヤ `nicola`（単独面）のキーの定義 | `キー (t! unshifted キー 文字)`。送出できる文字の無いキーは、キーそのもの（`1 1`） |
| レイヤ `nicola-lthumb`・`nicola-rthumb`（左・右の親指の面）のキーの定義 | `キー (t! shifted キー 文字)`。送出できる文字の無いキーは `キー (t! shifted-raw キー)` |
| 文字の定義（1 文字につき 2 行） | `(defvirtualkeys (t! keysn 文字 送出のキー列))` と `(defalias (t! sendn 文字 送出のキー列))`。2 行の引数は同じにする。n は送出のキー列のキーの数（`lsft` も数える） |

`unshifted`・`shifted`・`shifted-raw`・`keysn`・`sendn` は、配列プロファイルの中で定義したテンプレート（kanata の `deftemplate`。`t!` で、引数を指定した定義に展開される）である。

送出のキー列は、その文字を入力するために、kanata が IME に送出するキーの並びである（「か」なら `k a`）。

編集手順は次のとおり。

1. レイヤのキーの定義の文字を変更する。例: `nicola` レイヤで `,` の単独面を「ね」から「っ」に変更する。

   ```lisp
   comm (t! unshifted comm ね)   →   comm (t! unshifted comm っ)
   ```

   キーの定義は面ごとに独立している。単独面を変更しても、親指の面（`nicola-lthumb`・`nicola-rthumb` の同じキーの定義）は変更されない。
2. 新しい文字の定義が配列プロファイルに無い場合は、文字の定義の並び（`(defvirtualkeys (t! keys…` の行）に 2 行を追加する。例: 「ゔ」（v u）。

   ```lisp
   (defvirtualkeys (t! keys2 ゔ v u))
   (defalias       (t! send2 ゔ v u))
   ```

   送出のキー列は、IME（Mozc）の既定のローマ字表に合わせる（`crates/nicola-kbdgen/src/encoder.rs` の表）。キーは、JIS 配列でその文字を入力するキーの kanata の名前で記述する（kanata のキー名は US 配列の位置なので、JIS の `:` キーは `'`）。Shift が必要な文字は、前に `lsft` を記述する（例: `！` は `(t! keys2 ！ lsft 1)` と `(t! send2 ！ lsft 1)`）。
3. 設定ファイルの記述に誤りが無いかを検査する（[§2.4](#24-編集した設定ファイルの検査)）。

**IME の設定で決まる文字:** 読点・句点（`、`・`。`）と全角のコンマ・ピリオド（`，`・`．`）は、送出するキーが同じで、どちらが入力されるかは IME の句読点の設定で決まる。面の文字をもう一方に変更しても、入力される文字は変わらない。中黒 `・` と全角のスラッシュ `／` も同じで、IME の記号の入力の設定で決まる。

**仕組みの説明:** 1 文字につき 2 行になる理由と、送出のキー列に `lsft` がある文字の扱いは[kanata の設定ファイルの設計 §2.2](kanata-kbd-design.md#22-送出の原子性)、命名規則（ローマ字を記述した面の名前を含む）は[kanata の設定ファイルの設計 §3](kanata-kbd-design.md#3-命名規則)にある。

### 2.3 注意点（kanata の制約）

設定ファイルに kanata の定義を追加・変更するとき（文字の定義の追加〔[§2.2](#22-文字の割り当ての変更)〕、環境固有設定への `defoverrides` 等の追加〔[§2.1](#21-環境固有設定user-customkbd)〕等）は、kanata の次の制約に注意する（そのほかの制約は[設計書 §10](design.md#10-kanata-の仕様と修正)にある）。

- 仮想キー（kanata の `defvirtualkeys` で定義し、ほかの動作から押す・離すキー）の動作で別の仮想キーを、テンプレートの本文で別のテンプレートを使用するときは、使用される方を先に定義する。レイヤと alias からは、定義の位置に関係なく使用できる。
- 1 つの `defalias`・`defvirtualkeys` に `t!` を多く並べない。kanata は `t!` を 1 つ展開するたびに、それを含むリスト全体を複製するため、読み込みが遅くなる。
- `switch` の条件に alias は記述できない（変数は記述できる）。
- `macro` は送出に使用しない（1 キーずつ順に送出するので、途中に Enter・Ctrl 等が割り込み、送出が崩れる）。

### 2.4 編集した設定ファイルの検査

kanata の `--check` で、設定ファイルの記述に誤りが無いかを検査する。誤りがある場合は、エラーの場所（設定ファイルの行）と、誤りの内容（`help`）が表示される。

```sh
kanata --check -c ~/.config/kanata-nicola/kbd/nicola.kbd
```

文字の割り当ての変更（[§2.2](#22-文字の割り当ての変更)）の誤りは、エラーの場所として、編集した行ではなく、テンプレートの定義の行が示されることがある。その場合は、`help` に表示される文字で設定ファイルを探す（例: `，`〔全角〕を `,`〔半角〕と記述したときは `help: Referenced unknown alias ,.`）。

| 誤り | エラーの場所 |
|---|---|
| 文字の定義に無い文字を、レイヤのキーの定義に記述した | テンプレート `unshifted`・`shifted` の定義の行 |
| 同じ文字を 2 回定義した | テンプレート `keysn` の定義の行 |
| `keysn`・`sendn` の数字と、送出のキー列のキーの数が合わない | 編集した行（`help` に、必要な引数の数〔文字とキーで n＋1〕が表示される） |

## 3. 設定ファイルの再生成

次の対象を変更するときは、設定ファイルを kanata 設定生成器で再生成する。`kbd/` の設定ファイルをそのまま使用する場合は不要である。

| 再生成で変更する対象 | 指定するオプション |
|---|---|
| 配列（配列差分ファイルを重ねる等） | `--layout`・`--overlay` |
| 親指キー | `--thumbs` |
| NICOLA 切替キー | `--toggle` |
| Ctrl として扱うキーのうち、修飾キーと `caps` 以外のキー（[§2.1](#21-環境固有設定user-customkbd)） | `--key-as-ctrl` |

親指キーと NICOLA 切替キーは、配列プロファイルの中のいくつもの定義（`defsrc`、レイヤ、alias）に記述されている。配列プロファイルを編集しても変更できるが、変更する箇所が多く、変更の漏れが起きやすい。

kanata 設定生成器は、リポジトリの直下で実行する（Rust が必要。実行方法とオプションは[実装仕様書 §2.1](implementation.md#21-実行方法とオプション)）。例えば、親指キーを Space と変換に変更して、コピー先（[§2](#2-設定ファイルの編集)）に出力する場合は、次のコマンドを実行する。

```sh
cargo run --release -p nicola-kbdgen -- --thumbs KEY_SPACE KEY_HENKAN --split -o ~/.config/kanata-nicola/kbd/nicola.kbd
```

kanata 設定生成器は、次のようにファイルを出力する。

- `-o` に指定したファイル（例では `~/.config/kanata-nicola/kbd/nicola.kbd`）に、配列プロファイルを出力する。既存のファイルは上書きされるので、編集していた箇所は、同じように編集する。
- `--split` を指定すると、環境固有設定を、`-o` に指定したファイルと同じディレクトリの `user-custom.kbd` に出力する（`kbd/` と同じ形）。既存の `user-custom.kbd` は上書きしないので、環境固有設定の項目にかかわるオプション（`--key-as-ctrl` 等）は、そこには反映されない。環境固有設定にも記述する（[§2.1](#21-環境固有設定user-customkbd)）。
